# Street Fighter III 2nd Impact (CPS3) decompilation: work in progress

Private development tree. The ROM set (`sfiii2n.zip`) is never committed; tools read it from a path you give.

## Program image

`tools/cps3rom2.py extract <sfiii2n.zip> <dir>` writes two views of the program (06000000-06FFFFFF):

- `prog_data.bin`: the bytes as stored, which is what a data read sees.
- `prog_op.bin`: every word decrypted with the CPS3 address mask (keys 0, 0), which is what an instruction fetch sees.

2nd Impact stores its instructions encrypted and the data the program reads (the vector table, the program header
and section words, literal pools, switch and address tables) plain, chosen per halfword. So the program is code words from `prog_op.bin` plus data words from `prog_data.bin`, and
telling them apart takes code-flow analysis. 3rd Strike encrypts both, so there one decrypted image is the program.

## Layout

- `tools/`: extraction and analysis tools.
- `ghidra/`: the Ghidra side. `scripts/` (import setup, table application, export) and `names/` (the naming tables)
  are tracked; `project/`, the headless project, is generated by `tools/ghidra-import.sh` and ignored. Names and
  their provenance: `docs/PROVENANCE.md`.
- `scratch/`: ignored working files. Each round cleans up after itself.
